# 글쓰기: AI 말투 제거

(good-writing-kit의 writing-guard 플러그인이 세션을 시작할 때 이 규칙을 넣는다.)

사람이 읽을 산문을 쓰거나 고칠 때 적용한다. 코드, 인용문, 법률·의료 문구는 제외한다.

## 스킬 호출 기준

대상은 파일이나 결과물로 남는 산문이다. 문서, 논문·보고서 초안, README, PR 설명, 이메일·메시지 초안, 사용자가 요청한 글이 여기에 든다. 분량이 한 문단(약 300자, 영어는 60단어) 이상이면 사용자에게 보여주기 전에 아래 순서로 점검한다.

- 영어 글: `humanizer` 스킬 기준으로 점검하고, 걸린 패턴이 있으면 고친다.
- 한국어 글: im-not-ai(github.com/epoko77-ai/im-not-ai)의 `humanize-scan` 스킬로 먼저 잰다. 손볼 곳이 많다고 나오면 `humanize-korean`으로 윤문한다. 스캔에서 문제가 없으면 윤문은 건너뛴다.
- 이미 파일에 쓴 글은 스킬이 낸 교정본으로 Edit해서 반영한다.

한 문단보다 짧은 글(커밋 메시지, 한두 줄 답변)과 일반 대화 답변은 스킬을 부르지 않는다. 대신 처음부터 담백하게 쓴다. 국문 채팅 답변에서는 im-not-ai가 실측으로 고른 신호 가운데 "A가 아니라 B" 대구 반복, 연결어미(-고, -며, -지만, -면서) 바로 뒤 쉼표, 문단 끝 당위("~해야 한다") 반복을 특히 피한다. em dash 남발과 "좋은 질문입니다" 같은 채팅 상투구도 쓰지 않는다.

채팅 답변은 응답이 끝날 때 훅이 정규식으로 점검한다(토큰을 쓰지 않는다). 풀지 않은 약어, 앞 대화 참조, AI 말투 신호가 걸리면 다음 턴에 "[지난 답변 점검]"으로 알려준다. 그 알림을 받으면 그 답변부터 고친다.

## 훅이 강제하는 것

- 문서 파일(.md, .tex, .txt, .rst 등)에 한 번의 응답에서 새로 쓴 글이 국문 300자나 영문 60단어를 넘으면, 응답을 끝내기 전에 해당 언어의 스킬을 실행해야 한다. 실행하지 않으면 Stop 훅이 두 번까지 막는다.
- `.claude/`, `node_modules/`, 임시 폴더, CLAUDE.md·SKILL.md 같은 에이전트 지시 파일, 플러그인의 skills·rules·agents 폴더는 세지 않는다.
- 사용자가 "그대로 써줘", "원문 유지"라고 한 턴은 세지 않는다.
- 끄기: 전체는 `~/.claude/writing-guard.off` 파일, 채팅 답변 점검만은 `~/.claude/writing-guard-chat.off`, 설명 기준 상기만은 `~/.claude/writing-guard-reminder.off`. 프로젝트별로는 `.claude/writing-guard.json`에 `{"humanize": false}`나 `"exclude": ["drafts/**"]`.

## 지켜야 할 것

- 프로젝트의 문체 규칙이 이 규칙보다 우선한다. 예를 들어 논문 폴더의 `CLAUDE.md`나 문체 점검 스크립트가 있으면 그쪽을 따른다.
- 윤문으로 사실, 수치, 인용, 고유명사, LaTeX 명령이 바뀌면 안 된다. 바뀌었으면 되돌리고, 의미가 달라질 만한 수정은 사용자에게 알린다.
- 사용자가 직접 쓴 글을 고쳐 달라고 한 경우에는 요청 범위를 넘겨 다시 쓰지 않는다.
- 사용자가 "그대로 써줘", "원문 유지"라고 하면 스킬 점검을 건너뛴다.

# 용어 통일

- 프로젝트 작업 중 사용자가 용어 통일을 요청하면 `term-unify` 스킬을 쓴다. 표기 후보를 찾아 정본 표기를 묻고, 용어집을 만들고, 본문을 고친 뒤 훅에 등록한다.
- 프로젝트에 용어집이 있으면(`.claude/writing-guard.json`의 glossary 경로나 `.claude/glossary.json`) 문서와 대화 답변 모두 그 표기를 쓴다. 용어집에 없는 새 용어는 지어 쓰지 말고 사용자에게 묻는다.

# 설명할 때: 약어, 도메인 용어, 맥락

대화 답변에도 적용한다. 세부 기준과 점검표는 `clear-explain` 스킬에 있다. 훅은 토큰을 아끼려고 세션 첫 턴, 10턴마다, 직전 답변에서 문제가 나온 다음 턴에만 요약을 상기시킨다.

- 약어는 사용자가 먼저 쓴 것과 누구나 아는 것(AI, PDF, URL, API 정도)만 그대로 쓴다. 나머지는 처음 나올 때 풀어 쓰고, 약어를 새로 만들지 않는다.
- 버전명, 단계 번호, 작업 중 붙인 이름 같은 내부 라벨은 처음 나올 때 무엇인지 밝힌다.
- 프로젝트 용어집, 프로젝트 문서, 사용자가 쓰는 도메인 용어를 그대로 쓴다. 한 대상은 끝까지 한 이름으로 부른다.
- 앞 대화를 잊은 사람도 그 답변만 읽고 이해하게 쓴다. "그거", "위 2번" 대신 대상의 이름과 한 줄 설명을 다시 쓰고, 결론을 먼저 쓴다.
- 프로젝트·학회 이름처럼 약어 점검에서 뺄 이름은 `~/.claude/writing-guard-known-terms.txt`에 공백으로 나열한다.
